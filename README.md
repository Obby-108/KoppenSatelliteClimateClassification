# Introduction

---

This repository contains the main source code for the Köppen-Geiger Sentinel-2 Satellite Climate Classification final project for CS 6140: Machine Learning.
Before setting up the project, make sure you have downloaded the dataset [here](https://northeastern-my.sharepoint.com/:f:/r/personal/salchert_b_northeastern_edu/Documents/cs6140_climate_project_data?csf=1&web=1&e=r2y4k5).

To ensure the project sees the dataset, please make sure that the dataset folder is named `data` and is located inside the project root directory.
The relative filepath should look like this:

`KoppenSatelliteClimateClassification\data`

# Setup

---

To set up the project, first you must create the Conda environment with the required dependencies.
First, make sure Conda is installed.
You can find the installation instructions [here](https://docs.conda.io/projects/conda/en/stable/user-guide/install/index.html).

We recommend using PyCharm as your IDE for running the project, though any IDE should work.
Open your terminal and navigate to the project root directory.
Then, run

`conda create env -f environment.yml`

to create the Conda environment for the project.

After creating the environment, activate it using the command:

`conda activate climate_project_env`

PyTorch can create some conflicts when included in the `environment.yml` file, so you will need to install it manually using the following Pip command:

`pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124`

At this point, the environment setup is complete.
If you are using PyCharm, navigate to Settings → Python → Interpreter and add a new local interpreter.
Choose "Select existing", select the type as "Conda", and then select `climate_project_env` as the environment.
Press "OK" on all windows.

The project is now ready to run!

# Usage

---

Once the project is set up, open up the `/model` directory.
This is where all the Jupyter Notebook scripts are contained.
Running each of these scripts will train a different model on the data.

### Logistic Regression

Running `logreg.ipynb` will train a Logistic Regression model on the satellite data.
This is the most basic model, and performs the worst on the dataset.

### Support Vector Machine (SVM)

Running `svm.ipynb` will train a One-versus-Rest (OvR) SVM on the satellite data.
Note that this script uses a simplified version of the dataset loaded from `svm_ready_data.h5`.
This file flattens the image data into a 5-statistic summary for each of the 12 satellite bands, providing 60 features per image.
The data file can be generated by running `svm-loader.ipynb`, although the file is provided in the repository already.

### Ensemble Methods

Running `ensemble.ipynb` will train both a Random Forest Classifier and a Gradient Boosting Classifier on the satellite data.
These ensemble methods perform comparably to the SVM, although they are outperformed by the neural networks, which indicates that the spatial features of the images are truly important for the classification task.

### Convolutional Neural Network & Transformer

Running `train.ipynb` will execute the main training script for the deep neural networks, including a Convolutional Neural Network (CNN) and a Vision Transformer (ViT).
The training script calls a function in the last cell called `run_kfold()` that executes K-Fold Cross Validation for the specified model type.
To switch model types or test different hyperparameter values, simply edit the arguments of the function call.
For example, to run the training script on the `SwinClimateTransformer`, use the following call:

```
models = run_kfold(
    model_type=SwinClimateTransformer,
    files=train_val_files,
    k=5,
    batch_size=256,
    lr=1e-4,
    weight_decay=0.05,
    num_epochs=epochs
)
```

Note that you may need to reduce the batch size depending on how much VRAM is available on your machine.

The training script will automatically generate the `\models` and `\reports` directories for storing the output of this script.
The `\models` directory contains checkpoints for the model parameters saved during training as well as the final model weights.
The `\reports` directory contains plots for training/validation loss, training/validation accuracy, and testing F1-score for each fold of training, as well as validation confusion matrices for each epoch in each fold.
